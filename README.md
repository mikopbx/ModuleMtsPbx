## Module description ##

We are working on the module developing guide here [https://docs.mikopbx.com](https://docs.mikopbx.com/mikopbx-development/)

## Несколько порталов MTS

Порталы MTS Автосекретарь задаются в настройках модуля (API ключ, смещение времени, вкл/выкл), у каждого своя позиция синхронизации. Портал, перенесённый из однопортальной версии, сохраняет ID звонков `fs-mts-<callId>`; остальные порталы получают `fs-mts-<ID портала>-<callId>`, а в событиях реального времени — `<ID портала>-<CallID>`. События MTS всех порталов принимаются на один адрес `/pbxcore/api/mts-pbx/v1/event` с общими «Логин REST»/«Пароль REST»; портал определяется по полю `Domain`.

## Авторизация выдачи истории в 1С

`GET /pbxcore/mts-pbx/cdr` требует Basic Auth («Логин REST»/«Пароль REST»), если включён флаг «Требовать авторизацию для выдачи истории звонков». Для новых установок он включён, при обновлении модуля — выключен. В обработке `ЗагрузкаИсторииЗвонковMtsPBX_v2` адрес АТС задаётся как `логин:пароль@адрес`.

## Ручной перенос истории звонков в 1С

Автономный экспортёр читает основную SQLite-базу CDR напрямую и не загружает классы модуля:

```bash
php bin/exportCdrTo1C.php \
  --from="2026-07-16 20:55:11" \
  --filter-for-1c \
  --output="/tmp/cdr-history.xml"
```

Путь к базе по умолчанию — `/storage/usbdisk1/mikopbx/astlogs/asterisk/cdr.db`. При необходимости его можно изменить параметром `--database=/path/to/cdr.db`. Граница `--from` включительная; если параметр не указан, используется `2026-07-16 20:55:11`.

Флаг `--filter-for-1c` включает подготовку сокращённой истории: у отвеченного звонка остаются только CDR со статусом `ANSWERED`, а у входящего пропущенного — одна строка вызова номера `2003`. Без флага экспортируются все строки `cdr_general`.

Для загрузки установите в 1С файл `ЗагрузкаИсторииЗвонковMtsPBX_v2.epf`, откройте его форму и нажмите «Загрузить из XML». Существующая синхронизация с АТС и её `offset` сохраняются и не изменяются ручным импортом.

Перед массовой загрузкой сделайте резервную копию информационной базы 1С. Записи ищутся по `entire_id`, поэтому повторная загрузка обновляет уже найденные звонки, но резервная копия всё равно необходима.
